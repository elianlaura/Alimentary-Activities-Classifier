# Alimentary Activities Classifier: diffusion-based synthetic pretraining for drink / eat / other recognition

Code to reproduce and extend the experiments of *"Diffusion-Based Synthetic Data Pretraining for
Enhancing Activity Recognition"* (E. Riveros, D. Vega-Oliveros, A. Soriano-Vargas, A. Rocha): a
CABiGRU classifier (Conv1D + bidirectional GRU + multi-head attention) for 5-s smartwatch windows
(accelerometer, gyroscope, magnetometer; 500 x 9), pretrained by reconstructing synthetic windows
generated by a PaD-TS diffusion model, then fine-tuned on real data.

> **Status (2026-09).** The paper is under revision. An audit of the archived runs found problems in
> the submitted results (baseline, generator architecture, test-subject leakage, test-set model
> selection). They are listed in [docs/REPRODUCIBILITY.md](docs/REPRODUCIBILITY.md). The pipeline
> below fixes them and adds the experiments requested by the reviewers
> ([docs/REVIEW_RESPONSE.md](docs/REVIEW_RESPONSE.md)).

## Layout

```
deo/                 python package: data I/O, splits, normalisation, models, metrics, corpora
scripts/             one script per pipeline stage + analysis, complexity, figures, legacy check
pad_ts/              PaD-TS diffusion model (attention and BiGRU variants) + train_deo.py / sample_deo.py
slurm/               cluster-agnostic Slurm launchers (settings in configs/cluster.env)
configs/             cluster.env.example
environment/         conda environments: deo-tf (TensorFlow 2.20) and deo-padts (PyTorch 2.2)
splits/              deo_legacy.json: the 55/10/29 subject split used by every paper run
artifacts/legacy/    archived checkpoints + metric files behind Table I and Sec. IV-E (~34 MB)
legacy/              code snapshots of the archived runs (read-only provenance) and the ISCMI 2025 scripts
docs/                reproducibility audit, data, review response, architecture tables
```

## Quick start on a Slurm cluster

```bash
# 1. code and environments
git clone git@github.com:elianlaura/Alimentary-Activities-Classifier.git
cd Alimentary-Activities-Classifier
conda env create -f environment/deo-tf.yml
conda env create -f environment/deo-padts.yml

# 2. cluster settings: paths, partitions, account, GPU type, time limits
cp configs/cluster.env.example configs/cluster.env && nano configs/cluster.env
source configs/cluster.env

# 3. data: copy the source CSV(s) to $DATA_ROOT/raw (see docs/DATA.md), then convert
slurm/sub.sh cpu 06:00:00 prepare tf python scripts/prepare_data.py --data-root $DATA_ROOT \
    --deo-csv $DATA_ROOT/raw/fullraws3_vivabem012_drink0eat1another2_94u_nowspr_noaer_acc_gyr_mag__coord__5sec_100hz.csv \
    --samehand-csv $DATA_ROOT/raw/fullraws2_vivabem12_noaer_R_D_MA_MB_acc_gyr_mag__coord__5sec_100hz_6act.csv

# 4. sanity check: re-evaluate the archived Table I checkpoints (expects 0.9055 / 0.8655 / 0.8802 / 0.8338)
slurm/sub.sh gpu 02:00:00 legacy tf python scripts/reproduce_legacy.py --data-dir $DATA_ROOT/deo --out-dir $RUNS/legacy_eval

# 5. plan and submit the experiment grid (inspect $RUNS/plan/*.tsv after the dry run)
slurm/submit_pipeline.sh --dry-run
slurm/submit_pipeline.sh
```

Every task skips work that is already done (`done.json`, finished checkpoints), so a failed or
timed-out stage is fixed by resubmitting it: `slurm/submit_pipeline.sh --from 5` restarts at
pretraining. Generator training and sampling resume from their last checkpoint.

## Pipeline

| Stage | Script | Env | Output (`$RUNS/...`) |
|---|---|---|---|
| 0 prepare | `scripts/prepare_data.py` | tf | `$DATA_ROOT/deo/{X.npy, meta.csv, split.json, norm_train.json, dataset_table.csv}` |
| 1 generator data | `scripts/make_generator_data.py` | tf | per-class segments of the **training subjects only** |
| 2 generator training | `pad_ts/train_deo.py` | torch | `generators/{gru,attn}_{drink,eat,other}_w24/` |
| 3 sampling | `pad_ts/sample_deo.py` | torch | `generators/*/samples_shard*.npy` (sensor units) |
| 4 corpora | `scripts/build_corpus.py` | tf | `corpora/<name>/corpus.npy` (float16) + manifest |
| 5 pretraining | `scripts/pretrain.py` | tf | `pretrain/<corpus>/seed<k>/autoencoder.keras` |
| 6 fine-tuning | `scripts/finetune.py` | tf | `finetune/<dataset>/<condition>/seed<k>/` metrics, predictions, history |
| 7 analysis | `scripts/analyze.py` | tf | `analysis/{summary.md, comparisons.md, volume_curve.pdf, learning_curves.pdf, class_balance.csv, cost.csv}` |
| extra | `scripts/complexity.py`, `scripts/plot_synthetic.py`, `scripts/describe_models.py` | tf | complexity table, real vs synthetic figure, layer tables |

Corrected protocol (differences with the archived runs in `docs/REPRODUCIBILITY.md`): fixed
subject split; generators trained per class on training subjects only; both stages z-scored with
training-subject statistics; one fixed fine-tuning configuration (deep head, lr 1e-4, focal loss,
<= 50 epochs); best epoch chosen on validation balanced accuracy; test evaluated once per seed;
probability-based mAP/AUC reported next to the legacy hard-label values.

## Experiment grid (`scripts/plan.py`)

Pretraining corpus sizes are in units of **R** = 21,138 real drink + eat training windows (the
legacy corpus had ~40 R). Defaults: 5 seeds, main volume 10 R.

| Experiment | Conditions | Reviewer items |
|---|---|---|
| main | `scratch`, `real_all` (SSL on real training windows), `diff_gru_x10`, `diff_attn_x10` | R3-01, R1-06, R3-02 |
| controls | `augment_x10`, `noise_x10`, `surrogate_x10` (same number of windows as `diff_gru_x10`) | R1-06 |
| volume | `diff_gru_x{1,2,5,10,20,40}` (nested corpora) | R1-05, R3-03, S-18 |
| scope | `diff_gru_all_x10` (synthetic drink, eat **and** other) | R3-02 |
| samehand | `scratch`, `real_all`, `diff_gru_x10` on the same-wrist dataset | R2-06, R1-03 |
| legacy | the archived recipe (raw units, archived pretrained backbone) with 5 seeds | R3-01 |
| heads (opt-in) | light / balanced / classic heads on `diff_gru_x10` | R3-02 |

Choose a subset with `slurm/submit_pipeline.sh -- --experiments main controls samehand legacy --seeds 3`.
Other options: `--multipliers`, `--main-multiplier`, `--gen-window 500` (generate whole windows
instead of 24-step segments), `--pretrain-args "--epochs 10"`, `--finetune-args ...`.

**Compute (rough, from the legacy timings on the original cluster).** Generator training
~1.1 s/step (100 k steps ≈ 30 GPU-h per generator, 5 generators); sampling ~7 ms per 24-step
segment (≈ 18 GPU-h for the 40 R drink corpus, split over `--sample-shards` jobs); pretraining
~0.8 GPU-h per R for 20 epochs (≈ 8 h at 10 R, 31 h at 40 R); fine-tuning 2-3.5 GPU-h per run. The
full default grid is on the order of 1,000 GPU-hours; `--seeds 3 --multipliers 1 2 5 10 20` roughly
halves it. Disk: ~8 GB per 10 R corpus (float16), ~15 GB of generator samples per 40 R class.

## Reproducing the archived numbers

`scripts/reproduce_legacy.py` evaluates the four checkpoints in `artifacts/legacy/` with the legacy
preprocessing. Those checkpoints are what the paper reported; the audit explains why the
comparison between them is not valid as published.
